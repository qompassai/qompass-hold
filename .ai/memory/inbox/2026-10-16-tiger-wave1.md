# 2026-10-16 — Tiger Style wave 1: first buildable, tested tree

Facts established during the solutions Tiger Style remediation wave 1
(tracker: ~/workspace/solutions-tiger-audit/ on Pax's VM):

- The crate did not build at all. First blocker: the pinned
  `oqs 0.10.1` crate fails to compile against its own vendored
  liboqs (18 errors inside the dependency). Root cause: `oqs`,
  `oqs-sys`, `libc`, and the `cc` build-dependency were declared
  but **never used** — no source file references oqs or libc, and
  there is no build.rs. All four are removed; if post-quantum
  support is wanted later, it returns as a deliberate, used
  dependency at a matched version.
- Second blocker (only visible after the first): the crate's
  `Error` never implemented zbus 5's `DBusError` trait, which the
  `#[interface]` methods require. It does now, delegating to the
  existing hand-written `dbus_error_name()`/`description()`
  mapping, so the D-Bus error names on the wire are unchanged
  (including the NotFound → `org.freedesktop.Secret.Error.NoSuchObject`
  special case). A test pins trait-vs-inherent agreement.
- Bug fix: `redb_imps::encode_int` silently wrote nothing for
  values above `u32::MAX`, which would corrupt the length-prefixed
  stream. It now returns an `InvalidInput` error and writes
  nothing; boundary and truncated-input tests cover the format.
- First real test suite: 21 tests (3 pre-existing + 18 new),
  validation + adversarial, covering the varint codec, the
  `RedbHashMap` redb value encoding, the error-mapping contract,
  the D-Bus path builders / `time_to_int` / `try_interface`, and
  `slugify`. slugify's current semantics are pinned deliberately:
  its outputs are on-disk collection IDs.
- Gates on primo 2026-10-16: `cargo build` (dev + release) ok,
  rustc warnings 0 (13 elided-lifetime warnings fixed via
  `cargo fix`), `cargo fmt --check` clean,
  `cargo test` 21/21 pass.
- Remaining debt, recorded not hidden: `cargo clippy` reports
  70 warnings — dominated by `result_large_err` (the `Error`
  enum is large because it wraps `zbus::Error`/`redb::Error`;
  boxing variants is a crate-wide design pass), plus redundant
  deref/borrow and `enum_variant_names`. That is a dedicated
  strict-clippy burndown, not a wave fix. No live D-Bus session
  test exists (tests are hermetic; the service needs a session
  bus and a `pass` store to smoke end-to-end).
